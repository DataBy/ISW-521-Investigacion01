Definición

¿Qué es React?

⚛️
Una biblioteca de UI

No es un framework completo. React solo se encarga de renderizar la interfaz. Es una biblioteca — para routing, datos, etc., eliges tus herramientas.

🧩
Basada en componentes

Divides tu UI en piezas pequeñas y reutilizables llamadas componentes. Como LEGO, las ensamblas para construir cualquier UI.

🔄
Reactivo al estado

Cuando los datos cambian, React actualiza automáticamente solo las partes de la UI que lo necesitan. Tú no tocas el DOM.

📦
Virtual DOM

Mantiene una copia en memoria del DOM. Compara cambios y actualiza solo lo necesario. Más eficiente que manipular el DOM real directamente.

Conceptos clave · 1/4

JSX — HTML con superpoderes

JSX es una extensión de JavaScript que te permite escribir algo que parece HTML dentro de tu código JS. No es HTML real: se compila a llamadas de React.createElement().

Regla clave: JSX siempre debe retornar un solo elemento raíz. Usa <div> o el shorthand <> para agrupar.

✓ Correcto
return (
 <div>
  <h1>Hola</h1>
  <p>Mundo</p>
 </div>
)
✗ Error
return (
 <h1>Hola</h1>
 <p>Mundo</p>
)

jsx-ejemplo.jsx
// JavaScript + HTML = JSX
function Saludo() {
  const nombre = "Byron";
  return (
    <div className="card">
      <h1>Hola, {nombre}</h1>
      <p>Bienvenido al taller</p>
    </div>
  );
}
// {} = JavaScript dentro de JSX
// className en vez de class
Conceptos clave · 2/4

Componentes & Props

Tarjeta.jsx
// Componente = función que retorna JSX
function Tarjeta({ titulo, descripcion, icono }) {
  return (
    <div className="tarjeta">
      <span>{icono}</span>
      <h2>{titulo}</h2>
      <p>{descripcion}</p>
    </div>
  );
}
// Usarlo — los props son como atributos HTML
<Tarjeta
  titulo="React"
  icono="⚛️"
  descripcion="Una biblioteca de UI"
/>
Reglas de componentes
→

Nombre con mayúscula. <Tarjeta> no <tarjeta>

→

Los props son de solo lectura. No los mutés dentro del componente.

→

Un componente, una responsabilidad. Si hace demasiado, sepáralo.

→

Reutilizable por diseño. Pasa datos distintos via props para distintos usos.

💡 Piénsalo así

Un componente es como una función: recibe datos (props), hace algo, y retorna UI. Puro, predecible, reutilizable.

Conceptos clave · 3/4

Estado & Hooks

¿Qué es el estado?

La memoria de un componente. Datos que cambian en el tiempo y que cuando cambian, React vuelve a renderizar la UI automáticamente.

Hooks principales
useState

Para guardar y actualizar valores simples (contador, texto, booleano).

useEffect

Para efectos secundarios: fetch de datos, timers, subscripciones.

useRef

Referencia directa a un elemento del DOM o un valor que no re-renderiza.

useContext

Para compartir estado entre componentes sin pasar props en cada nivel.

Contador.jsx
import { useState } from 'react';
function Contador() {
  // [valor, setter] = useState(valorInicial)
  const [count, setCount] = useState(0);
  return (
    <div>
      <p>Clicks: {count}</p>
      <button
        onClick={() => setCount(count + 1)}
      >
        Sumar
      </button>
    </div>
  );
}
// ⚠️ Nunca: count++ o count = count+1
// Siempre usa el setter: setCount(...)
Best practices

Buenas prácticas esenciales

✂️ Un componente = una tarea

Si un componente supera ~100 líneas o hace más de una cosa, divídelo. Más fácil de testear y reutilizar.

📤 Estado lo más local posible

El estado vive en el componente más cercano a quien lo necesita. No pongas todo en el componente raíz.

🔑 Keys únicas en listas

Al renderizar listas con .map(), siempre asigna una key única y estable. Nunca uses el índice del array.

🎣 Hooks solo al top level

Nunca pongas hooks dentro de condicionales o loops. Deben llamarse en el mismo orden en cada render.

📁 Estructura de archivos clara

Un archivo por componente. Nombres descriptivos. Agrupa por feature, no por tipo (components/, hooks/).

🧠 Componentes puros

Los mismos props deben producir el mismo JSX. Evita efectos secundarios en el render. Usa useEffect para ellos.

Conceptos clave · 4/4

Cómo piensa React

1
Render inicial

React llama al componente, obtiene el JSX, y lo convierte al DOM real.

2
Evento / cambio de estado

El usuario hace click, llega data nueva, cambia un prop. React se entera.

3
Re-render + Reconciliación

React vuelve a llamar el componente, compara el nuevo Virtual DOM con el anterior (diffing), y actualiza solo lo que cambió.

# 2. TarjetaPerfil.jsx
import { useState } from 'react';
function TarjetaPerfil({ nombre, rol }) {
  const [likes, setLikes] = useState(0);
  return (
    <div className="card">
      <h2>{nombre}</h2>
      <p>{rol}</p>
      <button onClick={() => setLikes(l => l+1)}>❤️ {likes}</button>
    </div>
  );
}
